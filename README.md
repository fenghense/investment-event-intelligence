# Investment Event Intelligence - 投资事件情报与证据时间线

## 项目简介

Investment Event Intelligence 是一个基于 AI 的投资事件情报产品，帮助用户看清同一投资事件在不同信息源（公告、新闻、研报、市场传闻）中的演化脉络，理清事件最初来源、事实变化、证据冲突、当前状态以及与关注标的的关系。

本产品基于 [扣子(Coze)](https://www.coze.cn) 平台搭建 AI 工作流后端，前端为轻量级 Web 展示页面。

---

## 目标用户

- **投资分析师**：需要快速追踪投资事件全貌，辅助投资决策
- **风控人员**：监控投资事件对持仓的潜在风险影响
- **金融研究员**：研究事件驱动的市场反应规律
- **合规人员**：追踪信息披露的及时性与一致性

## 核心设计

### 产品架构

产品采用"后端 AI 工作流 + 前端可视化展示"的架构：

```
用户输入(股票代码/事件关键词)
    ↓
[扣子后端] 事件采集与去重 -> 证据分级与时间线构建 -> 版本演化与状态追踪 -> 标的关联与影响分析
    ↓
[前端页面] 时间线视图 + 证据卡片 + 状态变更日志 + 标的关联面板
```

### 四大核心工作流

| 工作流 | 功能 | AI 角色 |
|--------|------|---------|
| 事件采集与去重 | 从多源信息中识别同一事件，去重合并 | 事件实体链接引擎：用语义理解提取事件核心要素（主体、动作、对象、时间）做匹配，而非简单关键词匹配 |
| 证据分级与时间线构建 | 对每条信息做来源可信度分级和事实类型标注，构建带时间戳的证据链 | 证据分级器：公告(最高) > 研报 > 权威新闻 > 社交媒体传闻(最低)；标注事实陈述/观点判断/推测/传闻 |
| 版本演化与状态追踪 | 识别信息状态变化（更新/否认/更正/过期），自动判断新信息对旧结论的影响 | 变更检测器：维护事件信息状态机（初始发布->更新补充->更正->否认->过期），重大变更时触发通知 |
| 标的关联与影响分析 | 关联事件涉及的标的，用行情/财务数据验证事件影响 | 影响分析师：关联股票/行业/板块，验证股价异动、成交量变化等市场反应 |

### 时间戳处理

产品区分四种时间维度：

| 时间类型 | 说明 | 示例 |
|----------|------|------|
| 事件发生时间 | 事件实际发生的日期 | 收购协议实际签署日 |
| 披露时间 | 公告/新闻首次公开发布的时间 | 公司在交易所发布公告的时间 |
| 抓取时间 | 系统首次采集到该信息的时间 | 爬虫抓取时间戳 |
| 更新时间 | 后续更正、补充或否认的时间 | 公司发布更正公告的时间 |

### 状态变更机制

事件信息存在以下状态转换：

- **更新**：新信息补充已有事件的细节，结论微调但不推翻
- **否认**：明确否定此前流传的信息，结论被推翻
- **更正**：修正此前信息中的错误内容，结论部分调整
- **过期**：事件因时间推移或条件变化而不再适用

当状态发生变更时，系统通过以下方式通知用户：

1. 前端页面实时刷新时间线状态
2. 邮件/站内信推送变更摘要（含变更前后对比）
3. 生成变更日志供追溯审计

## AI 角色详解

| AI 节点 | 输入 | 输出 | 关键技术 |
|---------|------|------|----------|
| 事件识别引擎 | 多源原始信息文本 | 去重后的事件清单(event_id) | LLM 语义理解 + 事件要素提取 |
| 证据分级器 | 去重后的事件 + 关联信息 | 带可信度评分和事实类型标注的证据链 | 来源权重规则 + LLM 分类 |
| 变更检测器 | 同一事件的多版本信息 | 状态演变图 + 变更通知 | 状态机 + LLM 差异分析 |
| 影响分析师 | 事件 + 行情/财务数据 | 事件-标的关系图谱 + 影响摘要 | 数据关联 + LLM 摘要生成 |

## 数据使用

### 数据源

| 数据源 | 数据类型 | 用途 |
|--------|----------|------|
| 扶摇 | 行情、财务、估值、特色数据 | 事件影响验证（股价异动、成交量变化等） |
| iFinD MCP | 公司公告、新闻、研报、互动记录、行业资讯 | 多源信息采集与事件追踪 |
| 公开权威材料 | 政府公告、交易所公告、权威媒体 | 数据源不可用时的 fallback 补充来源 |

### 数据来源标注

所有信息卡片均标注来源链接和抓取时间，确保可追溯。若使用公开权威材料替代商业数据源，会在来源字段明确标注"公开权威材料"及具体来源 URL。

## 已知边界

1. **数据源覆盖限制**：iFinD MCP 的数据覆盖范围取决于其自身数据源，部分小众标的或海外市场信息可能不完整
2. **LLM 事实核查的幻觉风险**：AI 生成的摘要和分析可能存在事实偏差，关键结论需人工复核
3. **实时性延迟**：从事件发生到系统采集、处理、展示存在时间延迟（预计 5-30 分钟），非严格实时
4. **语义匹配的准确率**：事件去重依赖 LLM 语义理解，对于高度相似但实质不同的事件可能存在误合并
5. **前端演示性质**：当前前端为功能演示版本，部分 API 调用使用模拟数据，生产环境需对接真实后端

## 技术栈

- **后端 AI 工作流**：扣子(Coze) 平台可视化编排
- **前端**：原生 HTML5 + CSS3 + JavaScript（无框架依赖）
- **数据接口**：扣子 API (REST) + 扶摇 API + iFinD MCP
- **部署**：GitHub Pages / Vercel / Netlify（静态前端）+ 扣子托管（后端）

## 快速开始

### 前端部署

1. 克隆本仓库
2. 用浏览器直接打开 `frontend/index.html` 即可预览演示版本
3. 如需对接真实后端，修改 `frontend/app.js` 中的 API 地址配置

### 扣子后端搭建

1. 登录 [扣子平台](https://www.coze.cn)
2. 参考本项目 README 中"四大核心工作流"章节，依次搭建四个工作流 Bot
3. 将 Bot 发布为 API 接口，获取 Endpoint 地址
4. 在 `frontend/app.js` 中配置对应的 API 地址
